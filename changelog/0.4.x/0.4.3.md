# 0.4.3 — 2026-09-30

## Added

- **`last_n_observations` on `imf_query_dataset`** ([#53](https://github.com/cyanheads/imf-mcp-server/issues/53)) — an integer from 1 to 10,000 that keeps each series' last N observations, inside `start_period`/`end_period` when either is set; `1` returns every series' latest value. It is echoed on the result and rendered as `**Last observations:** N per series`, and `observation_count` and staged tables count only the selection.

## Changed

- **`filter` (`imf_list_databases`) and `codelist_filter` (`imf_get_database`) match every word** ([#54](https://github.com/cyanheads/imf-mcp-server/issues/54)) — split on whitespace and commas, a filter keeps an entry when each word appears in one of its searched fields, so `"GDP constant prices"` finds `NGDP_RPCH`. A filter with neither separator matches as before, and the empty-match notices suggest fewer or shorter words.
- **The dataframe tools are listed only when DataCanvas is configured** ([#50](https://github.com/cyanheads/imf-mcp-server/issues/50)) — without `CANVAS_PROVIDER_TYPE`, `imf_dataframe_describe`, `imf_dataframe_query`, and `imf_dataframe_drop` leave `tools/list` and show disabled with the `CANVAS_PROVIDER_TYPE=duckdb` hint; `imf_dataframe_drop` still also needs `IMF_ENABLE_DATAFRAME_DROP=true`.
- **Error envelopes carry `data.requestId`, and a failure whose `data.reason` a tool declares carries that entry's recovery hint**, service-layer throws included (mcp-ts-core 0.13.10). Handlers no longer forward `ctx.recoveryFor`.
- **Docker image** — production dependencies install in a `$BUILDPLATFORM` stage cross-targeted with `--os`/`--cpu` instead of copying the build stage's `node_modules`, OpenTelemetry packages install through `scripts/install-otel.ts` at the framework's declared peer ranges, and base images move to `oven/bun:1.4.2`.
- Dev scripts, `framework-skills/`, and `CLAUDE.md`/`AGENTS.md` synced from the mcp-ts-core 0.13.10 scaffold; `.mcpbignore` excludes `docs/idea.md` and `logs/`, and the npm package excludes `dist/*.mcpb`.

## Fixed

- **Without DataCanvas, `imf_query_dataset` holds its 100,000-character response budget** ([#50](https://github.com/cyanheads/imf-mcp-server/issues/50)) — an over-budget result returned every observation inline; it now returns the longest time-ascending prefix that fits, with `truncated: true`, full `series_metadata`, and `retrieval_guidance` naming the last `time_period` returned and how to narrow. A key whose `series_metadata` alone overflows fails as `response_too_large`.
- **Key codes are checked against their dimension's codelist before the data request** ([#52](https://github.com/cyanheads/imf-mcp-server/issues/52)) — `US.NGDP_RPCH.A`, `USA.NGDP_RPC.A`, and `NGDP_RPCH.USA.A` read as missing coverage (`no_data`); they now fail as `invalid_key_code`, naming each code's position, dimension, up to five nearest codes (`US` → `USA`), and the dimension a misplaced code belongs to.
- **`*` inside a `+` list fails as `wildcard_in_code_list`** ([#52](https://github.com/cyanheads/imf-mcp-server/issues/52)) — the portal ignores it there, so `USA+*.NGDP_RPCH.A` returned USA alone.
- **Keys and `dataflow_id` are trimmed and resolved case-insensitively** ([#52](https://github.com/cyanheads/imf-mcp-server/issues/52)) — `usa.ngdp_rpch.a` and a padded key read as missing coverage, and `dataflow_id: "weo"` as `dataflow_not_found`. Both now resolve to the canonical `WEO` and `USA.NGDP_RPCH.A`, which the result echoes; `dataflow_id` resolves the same way in `imf_get_database` and `imf://database/{dataflow_id}`.
- **`scale` is described as the power of ten a series is published in, not a multiplier** ([#51](https://github.com/cyanheads/imf-mcp-server/issues/51)) — `value` already arrives in base units. `content[]` renders scale `"0"` as `published in units` and `"9"` as `published in units of 10^9` (was `no scale multiplier` and a bare `9`), under a `Value (base units)` column.
- **Availability requests name the dataflow as `agency,id,version`** ([#55](https://github.com/cyanheads/imf-mcp-server/issues/55)) — the portal resolves a bare id as `all:<id>(latest)`, which 404s for IMF.SPR's `GPT`, so `available_only` failed as a retryable `availability_unavailable` and `no_data` lost its coverage diagnosis there.
- **Staged DataCanvas tables declare their column types** ([#56](https://github.com/cyanheads/imf-mcp-server/issues/56)) — `value` `DOUBLE`, `decimals` `INTEGER`, the rest `VARCHAR`. Types were sniffed from the first 100 rows, so a series opening with whole numbers (ER `GTM.XDC_USD.PA_RT.M`) staged `value` as `BIGINT` and truncated every later fraction.
- **Observation `status` decodes when STATUS ships as an inline literal** ([#57](https://github.com/cyanheads/imf-mcp-server/issues/57)) — such observations reported `status: null`. A null value whose only status is `NA` or `n.a.` (any case) is now dropped as padding; one with any other status is kept.
- **`imf_query_dataset` `content[]` and errors** — table cells escape `|` and backticks from upstream text and flatten line breaks; a lone period bound reads `from <start>` or `through <end>`, on the Period line and in `no_data_in_range`; and a catalog failure during the structure fetch keeps its `dataflow_list_unavailable` reason instead of becoming `structure_unavailable`.
