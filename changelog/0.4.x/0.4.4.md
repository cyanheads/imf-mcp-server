# 0.4.4 — 2026-10-16

## Added

- **`missing_series` and `missing_series_count` on `imf_query_dataset`** ([#60](https://github.com/cyanheads/imf-mcp-server/issues/60)) — a `+` key whose requested series partly return nothing keeps the observations it has and lists up to 20 absent series in key order, each with the reason a query for it alone gives (`no_data`, or `no_data_in_range` with the range its data spans).
- **`unresolved_attributes` on `imf_query_dataset`** ([#62](https://github.com/cyanheads/imf-mcp-server/issues/62)) — when the extra request that recovers a dimension group's unit, scale, or decimals fails, the success result names the attributes left `null` and a retry or `*` key that reports them.
- **`reference_period` on `imf_query_dataset`** ([#64](https://github.com/cyanheads/imf-mcp-server/issues/64)) — index series carry their base period as published (`2010A`, `Multiple`) on `series_attributes`, `series_metadata[]`, and, where the dataflow publishes one (`CPI`), each observation. Staged tables gain `series_reference_period` and `reference_period` columns.
- **`requested_limit` and `applied_limit`** ([#65](https://github.com/cyanheads/imf-mcp-server/issues/65)) — echoed on `imf_list_databases` and `imf_get_database` only when `limit` exceeded the per-call maximum of 200.

## Changed

- **Limits above a per-call cap are served up to it instead of rejected** ([#65](https://github.com/cyanheads/imf-mcp-server/issues/65)) — `imf_list_databases` `limit` accepts up to 1,000 and `imf_get_database` `limit` up to 50,000, each returning a 200-row page whose notice or `next_offset` names the rest; `last_n_observations` accepts up to 1,000,000.
- **Blank optional inputs read as unset** ([#67](https://github.com/cyanheads/imf-mcp-server/issues/67)) — `""` or whitespace on `agency_id`, `version`, `filter`, `codelist_filter`, `dimension_id`, `limit`, `offset`, `include_vintages`, `available_only`, `canvas_id`, `output_mode`, and the period bounds behaves as omitted, and `last_n_observations` accepts a numeric string (`"1"`) as the other numeric inputs do. `agency_id` and `version` match case-insensitively, and a miss names the agency and version the dataflow exists under.
- **One 45-second budget per tool call** ([#70](https://github.com/cyanheads/imf-mcp-server/issues/70)) — every upstream request and retry a call chains shares it, so a hung portal settles before a client's 60-second timeout; caller cancellation still aborts at once.
- **Upstream data failures carry declared reasons** ([#69](https://github.com/cyanheads/imf-mcp-server/issues/69)) — `imf_query_dataset` reports a 5xx, unusable body, unreachable or timed-out portal, or spent budget as retryable `data_unavailable`, and HTTP 429 as retryable `rate_limited`. Messages no longer carry the upstream host or HTML body.
- **`imf_dataframe_query` declares both SQL failure reasons** ([#68](https://github.com/cyanheads/imf-mcp-server/issues/68)) — a file named in the SQL fails as `sql_not_permitted`, where it reached callers as the undeclared `sql_read_only`, and SQL that prepares but fails at run time fails as the now-declared `sql_execution_error`, which carries the canvas id.
- **`structure_unavailable` is retryable** on `imf_query_dataset`, `imf_get_database`, and `imf://database/{dataflow_id}`; caller cancellation there is no longer reclassified.
- Docker image drops musl variants of native packages (`scripts/prune-musl-packages.ts`) and moves to `oven/bun:1.4.3`; dev scripts, `framework-skills/`, `CLAUDE.md`/`AGENTS.md`, `.dockerignore`, `.gitignore`, `.env.example`, the CodeQL workflow, and `server.json` (`runtimeHint` `npx`) synced from the mcp-ts-core 0.13.15 scaffold.

## Fixed

- **`imf_dataframe_query` tables keep one cell per column** ([#59](https://github.com/cyanheads/imf-mcp-server/issues/59)) — `|`, backticks, and line breaks in cells and column names are escaped, and STRUCT/LIST values render as compact JSON. A single row too long for the 100,000-character budget is returned with long cells and names clipped, listed as `name: value` lines, or pointed to in `structuredContent.rows` instead of refused as `response_too_large`.
- **`imf_query_dataset` `content[]` lists every series' attributes** ([#61](https://github.com/cyanheads/imf-mcp-server/issues/61)) — one row per distinct unit, scale, decimals, and reference period combination with the series that share it, replacing a table cut at 20 series.
- **Empty and repeated `+` members are dropped from `key`** ([#63](https://github.com/cyanheads/imf-mcp-server/issues/63)) — `USA++GBR+USA` queries `USA+GBR` and `notice` names each position that lost one; a position of only empty members fails as `empty_key_segment` instead of `no_data` for code `+`.
- **A `+` list past the portal's URL limit fails as `key_too_long`** ([#69](https://github.com/cyanheads/imf-mcp-server/issues/69)) — naming the longest position, instead of an unclassified 400.
