# 0.4.2 — 2026-09-19

## Changed

- **Tool argument rejections return `InvalidParams` (-32602)** with `data.reason: "invalid_arguments"` and a synthesized `data.recovery.hint`, which `content[]` carries as a `Recovery: <hint>` line — dropped when the message already states the hint verbatim, as a pattern or enum rejection does.
- **Tool error text closes with a parenthesized term list** — `(reason canvas_not_found)`, `(reason dataflow_list_unavailable · retryable)` — carrying whichever of `data.reason` and `data.retryable` is set, so a caller can branch on those terms without parsing JSON.
- **`sessionMode: 'stateless'` is declared in `src/index.ts`** rather than left to `MCP_SESSION_MODE` — a deployment that sets nothing still serves stateless, and the env var still overrides when set to a meaningful value.
- **Ordinary negative-path tool errors (no coverage for a key, malformed SQL, an expired canvas) log at `warning` or `notice` instead of `error`.** Observability only — the wire response and `structuredContent` are unchanged.
- **Development skills moved from `skills/` to `framework-skills/`**, so a plugin host installing this server no longer auto-loads them. Dev scripts, `devcheck` config, docs, and packaging metadata are synced from the mcp-ts-core 0.13 scaffold, which adds `bun run audit:fix` and `.github/workflows/codeql.yml`.

## Fixed

- **A malformed `canvas_id` on `imf_dataframe_describe`, `imf_dataframe_drop`, `imf_dataframe_query`, and `imf_query_dataset` is rejected at argument validation, before the handler runs.** The minted shape (`^[A-Za-z0-9_-]{10}$`) is advertised in each tool's `inputSchema`, so the rejection is `InvalidParams` (-32602) with `data.reason: "invalid_arguments"` naming `canvas_id`. Previously the value reached the handler and surfaced as `canvas_not_found`, indistinguishable from an expired canvas.
