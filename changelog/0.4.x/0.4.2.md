# 0.4.2 — 2026-09-19

## Changed

- **Tool argument rejections return `InvalidParams` (-32602)** with `data.reason: "invalid_arguments"` and a synthesized `data.recovery.hint`; `content[]` text now ends with `Recovery: <hint>`.
- **Tool error text closes with `(reason <reason> · not retryable)`** whenever `data.reason` or `data.retryable` is set, so a caller can branch on those terms without parsing JSON.
- **`sessionMode: 'stateless'` is declared in `src/index.ts`** rather than left to `MCP_SESSION_MODE` — a deployment that sets nothing still serves stateless, and the env var still overrides when set to a meaningful value.
- **Ordinary negative-path tool errors (no coverage for a key, malformed SQL, an expired canvas) log at `warning` or `notice` instead of `error`.** Observability only — the wire response and `structuredContent` are unchanged.

## Fixed

- **A malformed `canvas_id` on `imf_dataframe_describe`, `imf_dataframe_drop`, `imf_dataframe_query`, and `imf_query_dataset` is rejected as a `ValidationError` (`canvas_id_malformed`) at argument validation, before any canvas lookup.** Previously it reached the handler and surfaced as `canvas_not_found`, indistinguishable from an expired canvas. The minted shape (`^[A-Za-z0-9_-]{10}$`) is now advertised in each tool's `inputSchema`.
