# 0.6.0 — 2026-11-12

## Added

- **`imf_query_dataset` `series_count`** — the number of distinct series on a staged result whose `series_metadata` is cut to 20 entries (#76).

## Changed

- **Breaking: `imf_dataframe_query` now refuses SQL that names a DuckDB internal metadata view (`duckdb_tables`, `duckdb_columns`, `duckdb_views`, `pg_tables`, `pg_index`, `pg_class`, `pg_namespace`, `pg_proc`, `sqlite_schema`) as a column alias (bare, quoted, any case), CTE name, table alias, or subquery alias, queries 0.5.0 answered correctly.** The framework's SQL gate applies it through `denySystemCatalogs`, and the `sql_not_permitted` recovery says to rename the alias.
- **Staged `imf_query_dataset` results carry a preview bounded by count** (#76) — the first 20 series in `series_metadata` and at most 100 `observations`, never cut to the response budget, so a staged result no longer fails as `response_too_large`. When the list is cut, `retrieval_guidance` prints `SELECT DISTINCT series_key, unit, scale, decimals, series_reference_period FROM <table_name> ORDER BY series_key`.
- **`no_data_in_range` `available_range.first` on a mixed-frequency key** names the shortest period on the earliest day (`1990-M01`; 0.5.0 said `1990`) (#74).
- **`imf_dataframe_describe`** reports each column's type as DuckDB spells it (`DECIMAL(10,2)`, `INTEGER[]`) and passes the call's signal to `describe()`.
- **The framework SQL gate** accepts `range()` and `generate_series()` with constant arguments, which 0.5.0 refused, and refuses every file path in `FROM` as `sql_not_permitted` ("names a file, not a staged table"), including one like `'/etc/hosts'` that 0.5.0 reported as `missing_table`.
- **DuckDB 2** names an unaliased lambda expression's column without the `main.` prefix.
- **`empty_key_segment`, `wildcard_in_code_list`, and `invalid_key_code`** render the key and codes they quote as code spans in `content[]`.
- `framework-skills/`, dev scripts, the changelog template, and `.env.example` (`MCP_JWT_EXPECTED_AUDIENCE`, `MCP_JWT_EXPECTED_ISSUER`) synced from the mcp-ts-core 0.13.22 scaffold.

## Fixed

- **`imf_query_dataset` orders observations by the dates each period spans** (#74), earliest first and the shorter period first on a shared first day (`1996-01-01, 1996-M01, 1996-Q1, 1996-S1, 1996 …`), where 0.5.0 sorted by label. Resuming a cut mixed-frequency result from its last `time_period` no longer skips rows; `series_metadata` and `series_attributes` follow the new order.
- **`time_period_end` is the last day with data, inclusive, as `YYYY-MM-DD`** (#72) — WEO reads `2031-12-31`, where 0.5.0 relayed the exclusive `2032-01-01`. It applies to `imf_get_database` with `available_only` and to `imf_query_dataset`'s `no_data` text and `data.availability`; an absent or non-date annotation is `null`. The availability cache key is versioned, so a persistent `STORAGE_PROVIDER_TYPE` refetches an entry 0.5.0 cached.
- **`imf_query_dataset` declares `canvas_not_found` and `canvas_capacity_exhausted`** (#75) with recoveries of its own. A stale `canvas_id` fails as `canvas_not_found` with a recovery to omit it, where 0.5.0 relayed the framework's hint to re-run this tool; `output_mode: "canvas"` at the canvas cap fails as `canvas_capacity_exhausted` (-32003, retryable).
- **`auto` mode at the canvas cap returns the budget-cut inline result** (#75), where 0.5.0 failed the call as `canvas_capacity_exhausted` — `staged: false`, `truncated: true`, with `retrieval_guidance` naming the cap and a held `canvas_id`. If its full `series_metadata` alone overflows the response budget, it fails as `response_too_large` (-32070) rather than `canvas_capacity_exhausted`.
- **`retrieval_guidance` on an unstaged cut no longer offers resuming from the last period when every returned row overlaps it** (#74, #75): that call would return the same rows, so it names only a narrower key and `CANVAS_PROVIDER_TYPE=duckdb` (canvas off) or a held `canvas_id` (at the cap).
- **`imf_dataframe_drop` `canvas_not_found` recovery** says the canvas expired with its tables and nothing is left to drop, not to re-run `imf_query_dataset`.
