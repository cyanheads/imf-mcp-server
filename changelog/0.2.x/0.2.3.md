# 0.2.3 — 2026-07-11

## Added

- **`dsd_version` / `structure_ref`** optional output fields on `imf_get_database` and the `imf://database/{dataflow_id}` resource — surface the underlying DSD's own version and id when a dataflow references a shared or independently-versioned structure (e.g. IIP → `DSD_BOP`). ([#12](https://github.com/cyanheads/imf-mcp-server/issues/12))

## Changed

- **`imf_list_databases` description and package/plugin metadata**: dropped the hardcoded `193` dataflow count (stale — the live catalog now returns 103 non-vintage / 222 total dataflows) from the LLM-facing tool description, `package.json`, `server.json`, `manifest.json`, both plugin manifests, README, and `docs/design.md`. The dynamic `total_count` output field was already correct and is now the only count surfaced. ([#13](https://github.com/cyanheads/imf-mcp-server/issues/13))

### Dependency bumps

- `@cyanheads/mcp-ts-core` `^0.10.9` → `^0.10.14` (0.10.13 supply-chain guard, 0.10.14 Docker `--ignore-scripts`)
- `js-yaml` (transitive, via `depcheck`) `3.14.2` → `3.15.0` — clears [GHSA-h67p-54hq-rp68](https://github.com/advisories/GHSA-h67p-54hq-rp68) (quadratic-complexity DoS in merge-key handling)
- `packageManager` `bun@1.3.11` → `bun@1.3.14`; Dockerfile base images and CI images follow
- **`@socketsecurity/bun-security-scanner`** `^1.1.2` added as a dev dependency and wired as `bunfig.toml`'s `install.security.scanner` — scans every package before install for malware, typosquats, and known CVEs
- **`bunfig.toml` `minimumReleaseAge`**: new 3-day hold (259200s) on freshly published package versions as a supply-chain guard, excluding `@cyanheads/mcp-ts-core` for same-day framework adoption
- `devcheck.config.json` `outdated.allowlist` gained `@duckdb/node-api` and `typescript` (`typescript` `^6.0.3` is held below the available `7.0.2` major)
- Re-synced 12 agent skills and the framework devcheck/lint/tree scripts to mcp-ts-core 0.10.14

## Fixed

- **`imf_get_database` codelist resolution** for IMF's `_PUB`-suffixed and shared DSDs — `fetchDataflowStructure()` now resolves the DSD from the dataflow's own `structure` URN instead of guessing `DSD_<flow>` (which returns HTTP 204 for both repro cases), and codelist lookup tries both the DSD's own id and its `_PUB`-stripped form (`CL_ER_INDICATOR_PUB` for ER, `CL_BOP_INDICATOR` for IIP). A 204 DSD response is now a definitive miss (`retryable: false`) instead of exhausting the retry budget before falling back. ([#10](https://github.com/cyanheads/imf-mcp-server/issues/10))
- **Dataflow identity** (`name`, `version`, `agencyId`) no longer gets overwritten by a shared DSD's own metadata — `imf_get_database` and the `imf://database/{dataflow_id}` resource both pin identity to the dataflow's own values while still inheriting dimensions and codelists from the (possibly shared) structure. ([#12](https://github.com/cyanheads/imf-mcp-server/issues/12))
