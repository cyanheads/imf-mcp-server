# 0.2.8 — 2026-08-06

## Added

- **`imf_list_databases` paging**: `limit` (default 50, max 200) and `offset` inputs; output gains `returned_count` and echoes `offset`, and `enrichment.notice`/`truncated` name the next `offset` when matches remain. An unfiltered call previously returned all 103 non-vintage dataflows at once. ([#29](https://github.com/cyanheads/imf-mcp-server/issues/29))
- **`imf_query_dataset` `series_metadata`**: a key resolving to more than one series (`+`, `*`) now carries a `unit`/`scale`/`decimals` entry per distinct `series_key`, in both `structuredContent` and the rendered table in `content[]` (capped at 20 rows, with the cap disclosed); `series_attributes` keeps describing the first series for the single-series case. ([#15](https://github.com/cyanheads/imf-mcp-server/issues/15))

## Changed

- **`imf_list_databases` descriptions shortened to 200 characters**: the full text is unaffected for `filter` matching and remains available from `imf_get_database` and the `imf://database/{dataflow_id}` resource. ([#29](https://github.com/cyanheads/imf-mcp-server/issues/29))
- **`imf_query_dataset` `content[]` Series line no longer drops on the `"0"` scale sentinel**: it previously omitted the whole line — including `decimals` — whenever scale was the sentinel and unit was absent; scale `"0"` now renders as `no scale multiplier` and every other attribute renders beside it. ([#18](https://github.com/cyanheads/imf-mcp-server/issues/18))

## Fixed

- **Per-series attributes no longer collapse to the last series decoded**: `ImfSdmxService.fetchData()` assigned `unit`/`scale`/`decimals` to one shared variable inside the series loop, so a `+` or `*` key returned one series' attributes for all of them. Attributes are now keyed per decoded series key (`seriesAttributesByKey`) and read through that key on the inline payload, the canvas rows, and the rendered table. ([#15](https://github.com/cyanheads/imf-mcp-server/issues/15))
- **`DECIMALS_DISPLAYED` resolved through its attribute definition instead of read as a raw index**: like `SCALE`, the series entry is an index into the attribute definition's `values`, not the digit count — WEO's `[0, 0, 0, …]` against `values: [{ id: "3" }]` reported 0 decimals for a series that displays 3. `resolveDecimalsValue()` now resolves through `values` when present and falls back to the literal entry when the definition ships none.
- **Empty dataflow no longer reported as an uncovered code**: `imf_query_dataset`'s `no_data` handler blamed the caller's first dimension code whenever `series_count` was 0, even for a dataflow that publishes no series at all (several `_VINTAGE` flows). A dataflow-wide availability probe (empty `firstDimensionCode`) now runs only on that path, distinguishes the two cases, and points recovery at `imf_list_databases` instead of a different code when the dataflow itself is empty. ([#31](https://github.com/cyanheads/imf-mcp-server/issues/31))
- **Series-attribute decode no longer quadratic in series count**: selecting the first series for the flat `series_attributes` fallback recomputed the accumulated map's size on every iteration; a `*` key on a wide dataflow resolves to tens of thousands of series, making the decode quadratic. A first-write-wins assignment replaces the recount.
