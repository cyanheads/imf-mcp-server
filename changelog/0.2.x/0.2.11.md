# 0.2.11 — 2026-08-06

## Fixed

- **`imf_query_dataset` no longer reports `unit: null` (and stale `scale`/`decimals`) for a `+` key with no `*`**: when a key combines codes with `+` on the dimension a group attribute is declared against, the portal ships that group's definition with empty `values` — on `WEO` it also omits `dataSets[0].dimensionGroupAttributes` entirely, on `PPI` it keeps the block but files only other groups' rows. `ImfSdmxService.fetchData()` now detects this shape and issues one bounded, non-retried `attributes=series&measures=none` request with the smallest non-group codelist widened to `*`, recovering the group's values and matching them back onto the original series by dimension code (the two responses order a dimension's `values` independently, so matching by index would land a value on the wrong series). Every other key shape — including the roughly 100 dataflows that declare a unit and genuinely publish none — still costs exactly one upstream request; a probe failure, timeout, or empty result leaves the query exactly as it answered before the probe existed. The now-obsolete key-shape caveat is dropped from the tool description and README. ([#34](https://github.com/cyanheads/imf-mcp-server/issues/34))
