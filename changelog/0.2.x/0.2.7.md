# 0.2.7 — 2026-08-06

## Added

- **`*` wildcard for `imf_query_dataset` key positions**: documented and enforced — `*.NGDP_RPCH.A` matches every code at a position. `start_period`/`end_period` also accept `YYYY-SN` (semi-annual) and `YYYY-MM-DD` (daily), the two period label shapes the portal emits that were previously unrecognized. ([#23](https://github.com/cyanheads/imf-mcp-server/issues/23))
- **`no_data_in_range` error reason**: `imf_query_dataset`'s `errors` contract gains a reason for a key whose data exists but falls entirely outside the requested range, distinct from `no_data` (no upstream coverage at all); it reports the range the series actually spans. ([#22](https://github.com/cyanheads/imf-mcp-server/issues/22))
- **`empty_key_segment` error reason**: a blank `key` position (`USA..A`) is now rejected before the upstream call instead of silently matching zero series and surfacing as a misleading `no_data`. ([#23](https://github.com/cyanheads/imf-mcp-server/issues/23))
- **`imf_query_dataset` `enrichment.notice`**: fires when a period bound is set and some returned observations carry a `time_period` label the range filter cannot parse, naming the count and a sample so an unfiltered row is never mistaken for one that matched the range. ([#21](https://github.com/cyanheads/imf-mcp-server/issues/21))

## Changed

- **`AvailabilityResult.available_codes` shape**: each dimension's value changed from a bare `string[]` to `{ codes: string[], count: number }` — `count` is the pre-cap total, `codes` the up-to-20 preview. The `no_data` message now states how many of how many it is showing (e.g. `INDICATOR: 20 of 46 codes with data shown (…)`) instead of presenting a silent slice as the complete set. ([#26](https://github.com/cyanheads/imf-mcp-server/issues/26))

## Fixed

- **`end_period` no longer excludes finer-grained periods it names**: period bounds now compare as the date span they cover rather than as normalized label strings, so `end_period: "2023"` correctly includes `2023-M12` and `2023-Q4` (previously only `start_period` behaved this way, dropping the final year of monthly and quarterly series). ([#21](https://github.com/cyanheads/imf-mcp-server/issues/21))
- **Shared-DSD dataflow description no longer overwritten**: `imf_get_database` and the `imf://database/{dataflow_id}` resource returned a sibling dataflow's description whenever the queried flow shared a DSD (`BOP` returned `IIP`'s description). `normalizeDsd()` now matches the dataflow entry by id instead of taking the payload's first entry, and the flow's own description wins over the DSD's rather than the reverse. ([#30](https://github.com/cyanheads/imf-mcp-server/issues/30))
