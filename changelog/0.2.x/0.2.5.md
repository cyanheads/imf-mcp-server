## Fixed

- **`imf_dataframe_query` truncation surfaced**: DataCanvas's `truncated` flag now reaches `structuredContent` and `content[]` as a `truncated` output field; `row_count` is documented as the number of *materialized* rows (equal to the cap when `truncated` is true) rather than a pre-cap total that DataCanvas never reports. `format()` appends a paging note (stable `ORDER BY` plus `LIMIT`/`OFFSET`) when a result is capped. ([#16](https://github.com/cyanheads/imf-mcp-server/issues/16))
- **`imf_dataframe_query` missing-table recovery**: a `missing_table` error from the canvas layer is now translated into the tool's own declared `errors` contract instead of surfacing the framework's raw recovery hint, which named `registerTable()`/`describe()` — neither callable over MCP. Recovery now points to `imf_dataframe_describe` and `imf_query_dataset`. `canvas_not_found`'s wording was also tightened from "DataCanvas table" to "DataCanvas session" on both `imf_dataframe_query` and `imf_dataframe_describe`, now that `missing_table` covers the table-specific case. ([#17](https://github.com/cyanheads/imf-mcp-server/issues/17))
- **`imf_dataframe_query` rejected `WITH … SELECT`**: the pre-canvas shape check now accepts a leading `WITH` as well as `SELECT`, matching the framework's own SQL gate — which types `WITH … SELECT` as `SELECT` and allowlists CTE plan operators. Added a `sql_not_permitted` contract entry for read-only-gate denials (external-data/PRAGMA functions, system-catalog access, disallowed plan operators), kept distinct from `invalid_sql`. ([#25](https://github.com/cyanheads/imf-mcp-server/issues/25))

## Security

- **Dataflow-list URL leak**: `ImfSdmxService.fetchDataflows()` now wraps its retry pipeline in an error boundary, matching the DSD-path pattern already applied in 0.1.1. A failed dataflow-list request previously surfaced the framework's raw fetch error — including the fully-resolved, configurable `IMF_BASE_URL` — through every entry point that depends on the catalog (`imf_list_databases`, `imf_get_database`, `imf_query_dataset`, and the `imf://database/{dataflow_id}` resource, whose error additionally carried the raw upstream response body). The failure is now logged server-side and rethrown as a controlled `serviceUnavailable` with reason `dataflow_list_unavailable`; all four entry points declare it, including `imf_list_databases`, which previously declared no `errors` contract at all. ([#24](https://github.com/cyanheads/imf-mcp-server/issues/24))
