# 0.5.0 — 2026-10-29

## Added

- **`imf-guide` Agent Skill** — served over MCP through `createApp({ skills: 'skills' })` as the resource `skill://imf-guide/SKILL.md` and the resource template `skill://{+path}`. It routes a macro question to the dataflow that holds it and covers projections, group aggregates, and currency units. `skills/` ships in the npm package and the Docker image. `tools/list` is unchanged.
- **Root `plugin.json` and `mcp.json`** — the Agent Plugins 1.0.0 pair beside `.claude-plugin/` and `.codex-plugin/`.

## Changed

- **DataCanvas default** — DataCanvas is on by default: with `CANVAS_PROVIDER_TYPE` unset, large results spill to a DataCanvas table and `imf_dataframe_describe` / `imf_dataframe_query` are listed; set `CANVAS_PROVIDER_TYPE=none` to turn it off. The `.mcpb` bundle keeps it off.
- **`IMF_REQUEST_TIMEOUT_MS` must be an integer from 1 to 2147483647** — it feeds `AbortSignal.timeout()`.
- **An invalid server or framework variable, or a `.env` that cannot be read, stops startup with the framework's banner naming it** instead of a raw stack trace — the dataframe tool gates and the canvas default no longer parse the whole config, or throw, at module load.
- `imf_dataframe_query` logs a `response_too_large` failure at `warning` rather than `error`; the error the caller receives is unchanged.
- The Dockerfile build stage no longer installs `python3`/`make`/`g++`: dependencies install with `--ignore-scripts` and DuckDB ships prebuilt bindings, so nothing compiles there. Image base moves to `oven/bun:1.4.4`.
- `framework-skills/`, dev scripts, the bug report form, `.mcpbignore`, and `devcheck.config.json` synced from the mcp-ts-core 0.13.18 scaffold; `minimumReleaseAge` in `bunfig.toml` is 1 day (was 3).
- Dataflow counts in the package, plugin, and Docker descriptions read "100+" (was "hundreds" / 193).
